# 即売会 購入巡回表

同人誌即売会などの購入予定を日別に管理し、Excelで作成した会場マップ上へ配置して、訪問順や購入状況を扱うブラウザアプリです。

購入候補の編集、実行列の並べ替え、当日の状態更新、訪問先単位で確認する集中モード、会場マップ上の経路表示、イベント単位のExcel入出力、全データのJSONバックアップに対応しています。

> [!IMPORTANT]
> このアプリで扱うXLSXには、用途が異なる2種類があります。  
> **会場マップXLSX**はイベントの「マップデータ取り込み」から読み込みます。
> **イベント入出力XLSX**はイベント一覧の「Excel取り込み」（イベントがない場合は「Excelファイルを取り込み」）から読み込みます。
> 入口も内部形式も異なり、相互に置き換えることはできません。
>
> これらとは別に、イベント一覧の「JSONバックアップ保存」で、全イベントと関連設定をバージョン付きJSONとして保存できます。確実な移行・復旧にはJSONバックアップを使用してください。

## まず使ってみる

1. イベント一覧で「新規リスト作成」を選び、即売会名を入力します。
2. GoogleスプレッドシートのURL、CSV、表の貼り付け、または手入力で品目を登録します。
3. イベントを開き、「編集」モードで購入する品目を候補リストから実行列へ移します。
4. 会場マップを使う場合は、イベント一覧へ戻り、対象イベントの三点メニューから「マップデータ取り込み」を選びます。
5. 当日は「実行」または「集中」モードで、購入状況を更新します。
6. イベント一覧上部の「JSONバックアップ保存」から、全データのバックアップを定期的に保存します。イベント単位の受け渡しには「Excel形式で出力」も利用できます。

イベント作成時には、少なくとも1つの参加日が必要です。新規登録した品目は、各日の候補リストへ入ります。

## 購入リスト用スプレッドシート

### 推奨構成

Googleスプレッドシートから取り込む場合、次の条件を満たしてください。

- シート名を正確に `品目表` とします。
- 1行目には「サークル名」を含む見出しを置き、2行目以降をデータにします。新規取込はこの見出しを検出して読み飛ばし、更新時は1行目を常に見出しとして読み飛ばします。
- 列名ではなく、次表の**列位置**で読み取られます。
- URLを知っている未ログイン利用者がCSVとして取得できる閲覧権限にします。
- 共有URLは `/spreadsheets/d/スプレッドシートID/` を含む通常のGoogleスプレッドシートURLを使います。
- 手動非表示、基本フィルタ、フィルタビューで画面上から隠れている行も、元データの品目として取り込み・更新します。取り込み対象から外す場合は行を削除してください。

> [!WARNING]
> 新規URL取込は、データ行のA～Dがすべて埋まっているとA～D形式を先に読みます。次表のM～AA形式を使う場合は、データ行のA～Dを4列とも埋めないでください。更新処理は常にM～AA形式を使うため、継続更新するイベントには次表の構成を推奨します。

| 列  | 内容       | 必須 | 推奨値と取込時の扱い                                          |
| --- | ---------- | ---: | ------------------------------------------------------------- |
| M   | サークル名 | 必須 | 文字列。前後の空白は除去されます                              |
| N   | 参加日     | 必須 | `1日目`、`2日目` など。マップを使う場合はこの形式に統一します |
| O   | ブロック   | 必須 | マップのブロック名と同じ表記。既定設定では1～4文字が安全です  |
| P   | 番号       | 必須 | 半角数字で開始。`26a` も可。既定のマップ検出範囲は1～100です  |
| Q   | タイトル   | 任意 | 作品名など                                                    |
| R   | 価格       | 任意 | 0以上の整数。未定なら空欄にします                             |
| W   | 備考       | 任意 | 改行を含まない文字列を推奨します                              |
| Y   | URL        | 任意 | `https://` または `http://` で始まるURL                       |
| AA  | 数量       | 任意 | 1～20の整数。空欄は新規品目では1として扱われます              |

推奨するM～AA形式では、M～Pのどれかが空欄の行はエラーを表示せず取り込まれません。

価格は空欄なら「未定」になります。空欄以外では数字以外を除去して整数化するため、プレーンな0以上の整数を入力してください。数量同期では1～20の整数だけを反映します。既存品目の空欄は現在値を維持し、新規品目の空欄は1になります。0、負数、小数、文字列、21以上は警告され、新規行は追加されません。

セル内改行を含むCSVは正しく解析できない場合があります。サークル名、タイトル、備考などは1セル1行にしてください。

### Googleスプレッドシートの入力規則

次の規則を2行目以降へ設定し、「無効なデータを拒否」にすると入力ミスを減らせます。数式を使う規則は、各列の2行目を基準に指定します。

#### N列：参加日

「プルダウン」を選び、参加する日だけを登録します。

```text
1日目
2日目
3日目
4日目
```

先頭のゼロ、余分な空白、`1日目マップ` のような接尾辞は付けません。

#### O列：ブロック

最も安全なのは、別シートにブロック一覧を作り、「範囲からのプルダウン」で選ばせる方法です。大文字と小文字、半角と全角を含め、XLSXマップのラベルと同じ表記にします。

一覧を作らない場合は、既定のマップ検出設定に合わせた簡易規則として次を使えます。

```gs
=OR(O2="",AND(LEN(O2)>=1,LEN(O2)<=4,NOT(REGEXMATCH(TO_TEXT(O2),"[ 　]"))))
```

この規則は文字数と空白だけを検査します。記号を含むブロック名を使う場合は、マップ取込画面でも記号を許可してください。

#### P列：番号

既定のマップ設定に合わせ、先頭の半角整数が1～100で、任意の英字枝番と末尾数字を許可する例です。

```gs
=IF(P2="",TRUE,IFERROR(AND(REGEXMATCH(TO_TEXT(P2),"^[0-9]+[A-Za-z]*[0-9]*$"),VALUE(REGEXEXTRACT(TO_TEXT(P2),"^[0-9]+"))>=1,VALUE(REGEXEXTRACT(TO_TEXT(P2),"^[0-9]+"))<=100),FALSE))
```

`26a` や `26b1` は品目を区別する値として保持されますが、マップ上ではどちらも先頭数字の `26` へ対応します。番号範囲を変更する場合は、スプレッドシートの規則とマップ取込画面の最小値・最大値を同じにします。

#### R列：価格

```gs
=OR(R2="",AND(ISNUMBER(R2),R2=INT(R2),R2>=0))
```

表示形式で通貨記号や桁区切りを付けることはできますが、セルの実値は整数にします。

#### Y列：URL

```gs
=OR(Y2="",REGEXMATCH(TO_TEXT(Y2),"^https?://"))
```

#### AA列：数量

```gs
=OR(AA2="",AND(ISNUMBER(AA2),AA2=INT(AA2),AA2>=1,AA2<=20))
```

#### 必須列の入力漏れを強調する

条件付き書式を `M2:AA` に適用し、カスタム数式へ次を設定します。

```gs
=AND(COUNTA($M2:$AA2)>0,COUNTBLANK($M2:$P2)>0)
```

背景を赤系にすると、入力を始めた行でM～Pのいずれかが空欄の場合に気づけます。

同じ「サークル名・参加日・ブロック・番号」が重複した行を強調する場合は、別の条件付き書式として次を使います。

```gs
=AND(COUNTA($M2:$P2)=4,COUNTIFS($M$2:$M,$M2,$N$2:$N,$N2,$O$2:$O,$O2,$P$2:$P,$P2)>1)
```

この4項目は更新時の照合キーでもあります。同じキーを複数行で使うと更新対象が曖昧になるため、組み合わせが一意になるようにしてください。

### Googleスプレッドシートから新規作成する

1. 「新規リスト作成」で即売会名を入力します。
2. Googleスプレッドシートの共有URLを貼り付けます。
3. 取り込まれた品目と参加日を確認します。
4. 取り込まれない行がある場合は、まずM～Pの空欄を確認します。

同じ参加日・同じサークル名の行では、URLがある最初の行から、URLが空の兄弟行へURLが補完されることがあります。

### CSVと貼り付け

CSVでは、次のA～L形式を優先して読み取ります。

| 列  | 内容       |
| --- | ---------- |
| A   | サークル名 |
| B   | 参加日     |
| C   | ブロック   |
| D   | 番号       |
| E   | タイトル   |
| F   | 価格       |
| G   | 数量       |
| I   | 備考       |
| L   | URL        |

A～Dが見つからない場合は、Googleスプレッドシートと同じM、N、O、P、Q、R、W、Y、AAの位置を試します。CSV取込後の状態は未購入です。

表を直接貼り付ける場合は、**M、N、O、P、Q、R、Wの7列**をこの順番でタブ区切りにして貼り付けます。7列目は備考で、数量は1になります。URLは7列貼り付け本体の対象外ですが、同じ画面の「URL（7列貼り付け対象外）」欄へ行ごとに入力できます。6列や8列の行が混ざる場合は、列をずらさず全体を警告して取り込みません。CSVやGoogleスプレッドシート由来のURLは、妥当なHTTP(S) URLだけを取り込みます。

CSVファイルはブラウザの `File.text()` で読み込むため、UTF-8で保存してください。Shift_JIS専用の文字コード変換はありません。

既存イベントと同じ名前で新規作成しようとした場合、同じGoogleドキュメント・同じシートを参照していれば差分更新へ進みます。それ以外は、別名で作成するか、完全一致する重複品を除いて新規品目だけを追記するか、有効なGoogleスプレッドシートを新しい更新元として切り替えるかを選びます。

## 購入リストの更新と保護

Googleスプレッドシートから作ったイベントは、イベント一覧の三点メニューにある「アイテム更新」で再取得できます。追加、変更、削除の差分を確認してから適用します。

既存品目の照合には、サークル名、参加日、ブロック、番号を使います。これらを変更すると、元の品目を削除して別の品目を追加したものとして扱われ、購入状態や実行列の位置を引き継げない場合があります。

既存品目ではタイトル、カタログ価格、シート備考、URLが更新対象です。アプリで記録した購入金額、利用者メモ、購入状態、限数時の実購入数は同期しても変わりません。

数量は1～20の整数だけを同期します。未購入品目は差分確認後に更新し、購入済み・限数品目の予定数量は確認画面で明示的に許可した場合だけ更新します。既存の21以上の値は自動的に20へ丸めません。

品目カードの保護設定により、更新時の動作を制御できます。

| 保護設定     | 表からの変更 | 表から消えた場合の削除 |
| ------------ | -----------: | ---------------------: |
| 完全保護     |       しない |                 しない |
| 削除のみ許可 |       しない |               削除する |
| 保護なし     |     変更する |               削除する |

アプリ内で追加した品目は既定で完全保護、スプレッドシートから取り込んだ品目は既定で保護なしです。

保護なしの品目でも、実行・集中モードで購入状態、購入金額、予定数量、実購入数を変更すると、自動的に「削除のみ許可」へ変わります。その後の同期では品目の変更を上書きせず、更新元から消えた場合の削除だけを許可します。

## XLSX形式の会場マップを作る

### ファイルとシート名

- ファイル形式は `.xlsx` だけを使用します。`.xls`、`.ods`、`.csv` は会場マップとして読み込めません。
- シート名は `1日目`、`2日目` のように、数字の直後へ `日目` を付けます。
- 半角数字と全角数字のどちらも認識されますが、半角数字へ統一することを推奨します。
- `01日目`、`1 日目`、`1日目マップ` のような名前は避けます。
- イベント側に同じ参加日が先に登録されている必要があります。
- 1つの日に複数のマップシートを作らず、1シートへまとめます。
- 規則外の名前のシートは無視されるため、説明や凡例は `説明` などの別シートへ置けます。

### 最も安定するブロックの形

1つのブロックを、黒い太線で囲まれた1つの領域として作ります。ブロック名は2×2以上の結合セル、番号は通常セルにリテラル値で入れる構成が安定します。

```text
       A列       B列       C列   D列
    ┏━━━━━━━━━━━━━━━━━┳━━━━━┳━━━━━┓
 1  ┃                 ┃  1  ┃  2  ┃
    ┃  A1:B2を結合    ┣━━━━━╋━━━━━┫
 2  ┃  値は「A」      ┃  3  ┃  4  ┃
    ┗━━━━━━━━━━━━━━━━━┻━━━━━┻━━━━━┛
```

この例では、領域全体の外周だけをExcelの `medium` 相当の中太線、`thick` 相当の太線、または `double` 相当の二重線で連続して囲みます。内部の区切りは細線または線なしにします。ブロック名と番号の間を太線で分断しないでください。

### Excelでの作成手順

1. 購入リストを先に作り、実際に使う参加日、ブロック名、番号を確定します。
2. 新しいブックを作り、シート名を `1日目` などへ変更します。
3. ブロックごとに、ブロック名と少なくとも1つの番号を同じ領域へ配置します。
4. ブロック名セルを2×2以上で結合します。値は結合範囲の左上セルへ入力します。
5. 領域外周へ、黒い実線の「中」「太線」または「二重線」を設定します。
6. 番号セルには半角整数を直接入力します。数式は使用しません。
7. 通路は空欄かつ塗りつぶしなし、壁や通行不可部分は白以外で塗りつぶします。
8. 不要な装飾、特に通路の背景色と色付き太線を取り除きます。
9. `.xlsx` で保存します。
10. アプリの取込プレビューで、日別のブロック数、番号数、位置、回転角を確認します。

### マップセルの入力規則

Excelの「データ」→「データの入力規則」で、ラベルセルと番号セルへ別々の規則を設定すると安全です。

ブロック名の結合範囲では、左上セルだけを入力対象にします。次はA1を基準に、1～4文字かつ半角・全角空白なしとする例です。

```excel
=AND(ISTEXT(A1),LEN(A1)>=1,LEN(A1)<=4,LEN(A1)=LEN(SUBSTITUTE(SUBSTITUTE(A1," ",""),"　","")))
```

番号セルは「整数」、「次の値の間」、「1」と「100」を指定し、エラースタイルを「停止」にします。番号範囲を広げる場合は、アプリの取込設定も同じ範囲へ変更します。

同じブロック内の番号範囲へ、次のような条件付き書式を設定すると重複を発見できます。範囲と左上セルは実際の配置へ読み替えてください。

```excel
=AND(C1<>"",COUNTIF($C$1:$D$2,C1)>1)
```

数式でラベルや番号を生成した場合は、保存前に「値として貼り付け」へ変換してください。数式セルは表示値が見えても、番号として正しく認識されない場合があります。

### 既定のブロック検出条件

取込画面で条件を変更できます。通常は次の既定値に合わせてブックを作ると調整が少なく済みます。

| 条件                       | 既定値                               |
| -------------------------- | ------------------------------------ |
| ブロック名の最大文字数     | 4                                    |
| 使用できる文字種           | カタカナ、ひらがな、英字、漢字、数字 |
| 記号                       | 使用しない                           |
| 数字・記号だけのブロック名 | 使用しない                           |
| 1ブロックに必要な番号セル  | 1以上                                |
| 優先する結合セル数         | 4以上                                |
| 番号範囲                   | 1～100                               |
| 1領域の最大セル数          | 2,000                                |
| 輪郭判定しきい値           | 95%                                  |

「結合セル数4以上」は検出候補を優先する値で、4未満を必ず除外する条件ではありません。ただし誤検出を避けるため、ブロック名は2×2以上の結合を推奨します。

記号を使う設定では `-`、`.`、`/`、`_`、`+`、`&`、`#`、`*`、`!` が対象です。半角カナ、内部の空白、数字だけのブロック名は避けてください。

### セル書式がマップと経路へ与える影響

| Excel上のセル              | マップ取込                         | 経路探索       |
| -------------------------- | ---------------------------------- | -------------- |
| 半角整数                   | 範囲内ならスペース番号候補         | 通行不可       |
| 空欄、塗りつぶしなし       | 空きセル                           | 通行可能       |
| 文字列、塗りつぶしなし     | 表示文字。条件次第でブロック名候補 | 通行可能       |
| 白の塗りつぶし             | 実質的に塗りつぶしなし             | 通行可能       |
| 白以外のパターン塗りつぶし | 背景色として表示                   | 通行不可       |
| 外周の中線・太線・二重線   | ブロック境界の検出に使用           | 壁にはならない |
| 細線、破線、点線           | 主に表示用                         | 壁にはならない |
| フォント色                 | 文字色として表示                   | 影響なし       |

太い罫線はブロック検出には使われますが、経路の壁にはなりません。経路を通したくない場所には、白以外の塗りつぶしを設定してください。

一方、通路に装飾目的の背景色を付けると通行不可になります。色付きの凡例、行番号、列番号などもマップ本体へ置かず、規則外の名前を付けた説明シートへ分けてください。

### 作成時の重要な注意点

- 行の高さと列の幅は読み込まれず、アプリでは原則28pxの正方形セルとして表示されます。
- 非表示の行と列も読み込まれます。不要なら削除してください。
- 結合セルはセル数に応じて広がります。値は左上セルだけが使われます。
- 値が入っているセルから実データ範囲を決めるため、罫線や塗りつぶしだけの右端・下端は切り取られることがあります。
- 取込時に上下左右へ25セルずつ余白が加わるため、空白の外周を大量に作る必要はありません。
- 同じブロック名を離れた複数領域で使うと、1つのブロックとして統合されます。
- 同じブロック内に同じ番号が複数あると、上側、次に左側のセルが優先されます。
- 黒以外の太い罫線は、同色セルの関連付けにも使われます。単純なマップでは外周を黒に統一してください。
- グラデーションではなく、通常のパターン塗りつぶしを使ってください。

### 購入品目とマップの照合

照合は「参加日・ブロック・番号」で行います。

- `1日目` の品目は `1日目` シートへ対応します。先頭ゼロや余分な空白は使いません。
- ブロック名は前後の空白を除いた完全一致を優先します。完全一致がなく、大文字・小文字だけが異なる候補が1件に決まる場合は補完照合します。曖昧さを避けるため、同じ表記へ統一してください。
- 品目番号は、先頭に並ぶ半角数字だけがマップ番号になります。
- 品目番号 `26a` はマップの `26` へ対応しますが、`26a` と `26b` を別セルへ区別して配置することはできません。
- 品目番号 `A-01` や全角数字だけの値は安全に照合できません。ブロックはO列、番号はP列へ分けます。

最も確実なのは、スプレッドシートのP列とXLSXマップの番号セルを、どちらも同じ半角整数にする方法です。

### アプリへ取り込む

1. イベント一覧で対象イベントの三点メニューを開きます。
2. 「マップデータ取り込み」を選び、`.xlsx` ファイルを指定します。
3. 必要ならブロック検出条件を変更します。
4. プレビューを実行し、対象シート、ブロック数、番号数を確認します。
5. プレビュー後に表示される入力欄で、日ごとの回転角を0～359度で指定します。
6. 取り込みを確定します。
7. 各参加日のヘッダーにあるリスト／マップ切替で表示します。
8. 実行列へ品目を入れ、番号位置と経路を確認します。

同じ日を再度取り込む場合は、影響内容を示す確認画面が開きます。再取込対象となる各日の買い物品目、購入状態、実行列の順序、ルート表示のON/OFFと、同じXLSXの取込対象に含まれない日・他のイベントは維持されます。一方、旧マップ上の訪問地点、マップ由来のホール、該当ホールへの手動割り当て、ホール巡回順・訪問リスト、表示位置は初期化され、回転角は再取込のプレビュー画面で指定した値になります。

マップを使わない簡易ホール定義とその割り当て・順序は既定で保持されます。再取込の確認画面で、これらも削除するよう選択できます。確定後はホール領域、訪問順、経路を再確認してください。

## アプリの操作

### イベント一覧

イベント名を選ぶと購入巡回表を開きます。三点メニューから、次の操作ができます。

- Googleスプレッドシートからのアイテム更新
- 名称変更
- 会場マップXLSXの取り込み
- イベント単位のExcel形式で出力
- イベントの削除

イベント削除は取り消せず、品目、マップ、ルート、ホール情報も削除されます。先にJSONバックアップを保存してください。

既存イベントへ1件追加する場合は、イベントを開き、日付タブの横にある「アイテム追加」を選びます。参加日、ブロック、番号、価格、数量、備考、URLなどを入力できます。サークル名またはタイトルの少なくとも一方が必要です。

新規品目は、リストのスペース単位メニュー、マップセルのポップアップ、集中モードからも追加できます。マップセルから追加する場合は、その位置に対応する参加日、ブロック、番号を使って登録できます。

### 3つのモード

| モード | 用途                       | 主な操作                                                    |
| ------ | -------------------------- | ----------------------------------------------------------- |
| 編集   | 当日の訪問対象と順番を作る | 候補リストと実行列の間で品目を移動し、並べ替える            |
| 実行   | 会場で購入状況を記録する   | 実行列だけを表示し、状態や数量を更新する                    |
| 集中   | 次の訪問先へ集中する       | 1訪問先ずつ大きく表示し、同じ訪問先の複数品目をまとめて扱う |

モードはイベントの参加日ごとに選びます。イベントと参加日タブを開き、リスト表示のヘッダーにある「📝 編集」「🏃‍♂️ 実行」「🔍 集中」の各ボタンで切り替えてください。マップを表示している場合は、先にリスト表示へ戻します。参加日タブを約0.5秒長押しすると、編集モードと実行モードを素早く切り替えられます。

#### 編集モードの使い方

当日の実行列を作り、巡回順を整えるモードです。画面左側に「実行リストアイテム」、右側に「候補アイテム」が表示されます。

1. 対象イベントと参加日を選び、「📝 編集」を開きます。
2. 候補側でブロックを絞り込み、必要ならブロック順または番号順に並べ替えます。「優先」または「委託無」を利用者メモに含む候補があるブロックは、黄色で強調されます。
3. 候補品目を選択し、「選択したアイテムを実行列に移動」を選びます。1件ずつでも、チェックボックスや範囲選択を使った複数件でも移動でき、候補側から実行列へ直接ドラッグすることもできます。
4. 実行列では、ドラッグ操作または上下ボタンで巡回順を調整します。複数選択後の並べ替えボタンでは、選択部分を番号の昇順・降順にできます。
5. 当日回らない品目は実行列側で選択し、「選択したアイテムを実行列から戻す」を選びます。
6. 準備が終わったら「🏃‍♂️ 実行」または「🔍 集中」へ切り替えます。

同じスペースかつ同じ優先度に属する品目は、片方だけを選んでも同じ訪問先の品目としてまとめて移動されます。この場合、移動ボタンに「選択1件（移動2件）」のように、明示的な選択数と実際の移動数が表示されます。

候補側と実行列側を同時に選択すると列移動ボタンは表示されません。移動元の列だけを選択してください。PCではカードをドラッグし、タッチ端末ではカードを短く長押ししてから移動します。

「スペース別」を有効にすると、両方の列をスペース単位でまとめ、折りたたみ、スペース全体の選択、グループ単位のドラッグを利用できます。マップを取り込んでいる場合は、マップ上の番号から実行列への追加・除外、訪問リストからの詳細な順序編集もできます。

#### 実行モードの使い方

実行列だけを表示し、会場で購入結果を記録するモードです。

1. 編集モードで当日の実行列を準備し、「🏃‍♂️ 実行」を開きます。
2. 巡回順に品目を確認し、各カードの購入状態ボタンで「購入済」「売切」「欠席」「後回し」「遅参」「限数」などへ更新します。価格、予定数量、限数時の実購入数もカードまたは詳細編集から入力できます。
3. 既定の「スペース別」表示で、同じスペースの品目をまとめて扱います。展開したスペースの「全購入」「全売切」「全欠席」「全後回」「全遅参」「全限数」で、スペース内を一括変更できます。同じ一括ボタンをもう一度押すと、その対象を未購入へ戻します。限数以外への一括変更では、すでに限数となっている品目は変更されません。
4. スペース内の全品目が未購入以外になると、「スペースを閉じて次のスペースを展開」が表示されます。最後まで進むと、対象がある場合は「後回しでフィルタ」、続いて「遅参でフィルタ」へ移れます。
5. 画面下部で購入済み件数、限数の未入力件数、残り見込み金額を確認します。これらは現在の購入状態フィルタで表示中の品目を集計します。スペースナビを有効にしている場合は、ここから訪問先一覧も開けます。

ヘッダーの「巡回順」ボタンは、押すたびに「後回し」「遅参」「欠席」「売切」「未購入」「購入済」「限数」を順に切り替え、該当状態だけを表示します。ヘッダーを非表示にしている場合は、画面下部の同じボタンを使います。絞り込み中に状態を変更して対象外になった品目は、操作直後だけ「一時表示」として残ることがあります。「巡回順」へ戻すと実行列の順序で全品目を表示します。

「スペースを閉じて次のスペースを展開」や後回し・遅参フィルタへの移動では、価格未定の購入済み・限数品や、実購入数が未入力の限数品があると先へ進めません。該当欄を入力するか、必要な場合だけ設定でチェックを無効にしてください。購入状態ボタンの詳しい動作は、次の「購入状態」を参照してください。

編集・実行モードの検索欄では、現在の参加日にあるサークル名、タイトル、利用者メモを検索できます。Enterキーまたは「次を検索」を繰り返すと、一致品目を順番に強調表示して中央へスクロールします。ブロックや購入状態で絞り込んでいる場合、現在表示されている品目だけが検索移動の対象です。

#### 集中モードの使い方

実行列を1訪問先ずつ表示し、現在のスペースで必要な操作へ集中するモードです。同じ参加日・スペース・優先度の品目は、1つの訪問先にまとめて表示されます。

1. 編集モードで当日の実行列を準備し、「🔍 集中」を開きます。実行列が空の場合は「訪問先がありません」と表示されるため、「編集モードへ」から品目を追加します。
2. ヘッダーで現在のスペース、サークル名、処理済み件数、今回の支払額、現在のフェーズ、次の訪問先を確認します。
3. 各品目の購入状態、価格、数量を更新します。同じ訪問先をまとめて処理する場合は、ヘッダーの「全購入」「全売切」「全欠席」「全後回」「全遅参」「全限数」を使います。現在位置へ新規品目を追加する場合は、品目一覧末尾の「＋」を選びます。
4. PCレイアウトでは左右の前後ボタン、スマートフォンレイアウトでは左スワイプで次、右スワイプで前へ移動します。購入状態を変更しただけでは自動的に次へ進まないため、内容を確認してから明示的に移動してください。実行列の変更などで表示対象が空になった訪問先だけは、次の表示可能な訪問先またはフェーズへ自動的にスキップされます。
5. 通常フェーズの最後まで進むと、「後回し」の品目があれば後回しフェーズへ、その後「遅参」の品目があれば遅参フェーズへ進みます。後回し・遅参フェーズでは、その状態にした品目がある訪問先だけを再巡回します。
6. 全フェーズが終わると、状態別件数、購入合計、予定合計が表示されます。限数の実購入数が未入力なら一覧から修正でき、確認後は編集モードまたは実行モードへ戻れます。

フェーズ名の選択欄から「通常」「後回し」「遅参」を手動で切り替えることもできます。対象品目があり、以前の位置が残っているフェーズでは、最初から開始するか途中から再開するかを選べます。

集中モードをいったん離れて同じページ内で開き直したとき、正式な巡回中に購入状態を変更した履歴があるか、巡回が完了済みの場合は、次の再開位置を選べます。一時移動中の状態変更は品目へ反映されますが、「最後に購入状態を変更したスペース」には記録されません。

- 最後に購入状態を変更したスペース
- 離脱時のポインタ位置
- 現在のフェーズの最初
- 通常フェーズの最初

前後移動だけを行い、購入状態を変更していない未完了の巡回では、選択画面を出さず離脱時のポインタ位置から再開します。現在の実行列に対象がない場合、「最後に購入状態を変更したスペース」「現在のフェーズの最初」「通常フェーズの最初」の該当する選択肢は無効になります。「離脱時のポインタ位置」は選択できます。

この再開位置はアプリを開いている間だけ保持され、ブラウザ内の永続保存やJSONバックアップには含まれません。ページの再読み込みやブラウザの再起動後は進行ポインタが保持されません。購入状態、価格、数量などの品目データは、進行ポインタとは別に保存されます。

次へ進むとき、価格未定の購入済み・限数品や実購入数未入力の限数品があると移動が止まり、対象品目が強調されます。未購入の品目が残っているだけの場合は移動でき、移動後にチェック漏れの警告が表示されます。マップデータがある日はフッターからマップを併記でき、スペースナビから現在地への移動、一時移動、内容だけの確認もできます。

マップセルから一時移動すると、同じスペースにある全フェーズの品目をまとめて表示し、正式な進行位置は変えません。そこから初めて前後移動するときは移動基準のフェーズを選び、一時巡回の終端では、元のスペースへ戻るか、フェーズを選んで表示中のスペースを正式な現在地にします。「内容だけ確認」では状態・価格・数量の変更、品目の追加・編集・削除、一括変更、フェーズ変更、前後移動、スワイプが無効です。操作が必要になった場合は、上部の表示から一時移動へ切り替えます。

### 購入状態

通常の状態切替は、基本的に次の順で循環します。

```text
未購入 → 購入済 → 売切 → 欠席 → 後回し → 遅参 → 限数 → 未購入
```

「数量1の限数をスキップ」が有効な場合、循環方式では数量1の品目で「限数」を飛ばします。放射状メニュー方式では状態を直接選択でき、数量1で「限数」を選んだ場合は「購入済」か「限数」かを確認してから数量入力へ進みます。

「限数」は予定数量より少ない数量しか購入できなかった場合に使います。価格未定の購入済み・限数品や、実購入数が未入力の限数品があると、集中モードやスペースナビで次へ進めない場合があります。各チェックは設定で無効化できます。

実行画面の下部には、購入数、限数の未入力件数、残り見込み金額が表示されます。

「事後通販・頒布可否確認」は既定で有効です。実行・集中モードで品目を「売切」へ変更すると、通販、BOOTH、別イベント頒布、通販・別イベント頒布なし、未確認から回答できます。回答は利用者メモへ `通販･頒布確認: ...` として記録され、再回答時は同じラベルの記録を更新します。スペース単位で一括変更した場合は、対象品目を選んで共通または品目別に回答できます。

### スペースナビ

実行・集中モードでは、画面端の細い色付きレールまたは固定フッターの一覧ボタンから訪問先を開けます。実行モードでは現在の購入状態フィルタで表示中の訪問先、集中モードでは実行列のフェーズ別訪問先が対象です。両方の入口とも既定で表示され、レールは既定で左側です。色と斜線表示で、未購入、後回し、遅参、限数未入力、完了、価格・数量の入力不足を確認できます。

訪問先を選ぶと、「現在地として移動」「一時移動して操作」「内容だけ確認」を選べます。一時移動では正式な進行位置を変えずに品目を操作し、完了後に元の位置へ戻れます。「現在地として移動」または「一時移動して操作」で前方へ進む際は、価格未定の購入済み・限数品や実購入数未入力の限数品を検査し、未購入の訪問先を残す場合は確認を表示します。「内容だけ確認」と後方への移動では、この進行チェックを行いません。

### 表示と操作の設定

歯車ボタンから、テーマ、PC・スマートフォン向けレイアウト、表示倍率、保存状態の通常表示、実行・集中モードのヘッダー・タブバー表示、マップ番号セルの輪郭、購入時の入力チェック、数量1での限数スキップ、事後通販・頒布可否確認、状態ボタンの循環・放射状方式、スペースナビの表示と左右位置を変更できます。

テーマ、ヘッダー・タブバー・保存状態の表示、購入チェック、スペースナビ、スマート挿入の有効・方式などの端末設定はlocalStorageへ保存され、JSONバックアップには含まれません。PC・スマートフォン向けレイアウトの手動選択と表示倍率は現在のセッションだけに適用され、再読み込み時に初期状態へ戻ります。

### マップ、ホール、ルート

マップがある日だけ、ヘッダーへリスト／マップ切替が表示されます。切替ボタンの長押しから、訪問リスト、ブロック定義、ホール定義を開けます。

- マップ上の番号を選ぶと、その位置の品目を実行列へ追加または除外でき、同じ位置に新規品目も登録できます。
- 訪問リストではドラッグ、交換、範囲反転、優先度指定、元に戻す、やり直しができます。
- 訪問リストの変更は「確定」で保存します。
- 簡易ホール定義では、ホール名、色、所属ブロックを指定します。
- 詳細ホール定義では、マップ上の4～6頂点でホール領域を作ります。
- ホール順を並べ替え、必要なら実行列の順序へ反映できます。
- ルートは、現在日の実行列にある品目を、ホール順と優先度グループ順に並べて生成します。グループ内では実行列の順序を保ち、訪問順そのものを距離で最短化する機能ではありません。
- ホール定義後にルート線を表示する場合は、「すべて」ではなく対象ホールを選びます。
- スマート挿入では、候補品目をルート途中、指定訪問先の後、ホール末尾、リスト末尾などへ挿入できます。

場所が見つからない訪問先は除外され、場所が分かる訪問先だけで経路を作ります。詳細表示から対象のブロック・番号と品目を確認できます。通路が分断されて経路を作れない場合は、誤解を招く途中までの線を表示しません。マップ取込後に、通路が空欄・塗りつぶしなしで連続しているか確認してください。

番号セルと白以外で塗りつぶされたセルは通行不可として扱います。罫線は経路探索上の壁にはなりません。経路線は、上記の訪問順に並ぶ地点間を3×3のサブセル上のA\*探索で結びます。

## バックアップと復元

### 全データをJSONでバックアップする

イベント一覧上部の「JSONバックアップ保存」を選ぶと、すべてのイベント、品目、配置、日別モード、マップ、既存マップに紐づく回転と表示位置、ルート、会場設定、イベントごとのブロック検出条件を、バージョン付きJSONファイルへ保存します。これは通常のExcel入出力とは別の経路です。存在しないマップにだけ残った回転・表示位置設定は、バックアップの生成時と読み込み時に除外されます。

保存失敗表示からも、画面上の最新データをJSONバックアップへ退避できます。バックアップはアプリ側で暗号化されない平文JSONで、スプレッドシートURL、品目URL、備考なども含まれます。第三者へ渡す前に、共有してよい内容か確認してください。

テーマ、ボタンや保存状態の表示構成、チェック動作、スペースナビ、スマート挿入など、イベントに依存しない端末全体の表示・操作設定は復元対象外です。イベントを復元しても、現在の端末で使っている好みの設定は変わりません。

### JSONバックアップから復元する

1. イベント一覧上部の「JSONバックアップ復元」を選び、アプリが保存したJSONファイルを指定します。
2. バックアップ内から復元するイベントを選びます。
3. 推奨の「別名で復元」か、現在の同名イベントを置き換える「同名で置換」を選びます。
4. 検証と保存がすべて成功した後、復元したイベントが開きます。

ファイル形式、必須項目、型、品目IDや会場IDの参照が不正な場合は、復元前のデータを変更せず中止します。別名復元では既存イベントを変更せず、同名置換でも対象外のイベントは変更しません。

### イベント単位でExcel出力する

イベント一覧で対象イベントの三点メニューを開き、「Excel形式で出力」を選びます。簡易版は品目だけを出力します。完全版では品目とメタデータに加え、配置、マップ、ルートを含めるか選択できます。マップデータを含めた場合は、そのイベントのマップ回転、表示位置、ブロック検出設定もメタデータへ保存されます。イベント単位で受け渡す場合に使用し、全イベントの一括移行や災害対策にはJSONバックアップを使用してください。

ブロック定義はマップデータの中に常に含まれるため、復元したい場合は「マップデータ」を選びます。簡易版やマップデータを含めない出力にはブロック定義も含まれません。ホール定義とホール用のルート設定は「ルート情報」に含まれます。

出力ファイルには主に次のシートが含まれます。

- `アイテムデータ`：復元に必須
- `メタデータ`：完全版のみ
- `配置情報`：完全版で選択時
- `マップデータ`：完全版で選択時。画面用データとブロック定義をJSONで保持
- `ルート情報`：完全版で選択時。ルート、ホール定義などをJSONで保持

`マップデータ` シートは、セルと罫線で描いた会場マップではありません。会場マップXLSXの代わりに編集する用途では使えません。

Excel内の品目は、1～16列目を固定位置で読み取ります。バージョン2.2では、簡易版・完全版とも17列目に `カタログ価格`、18列目に `シート備考` を追加しています。この2列はヘッダー名で判定するため、ヘッダー名を変更しないでください。ファイルを手作業で編集する場合も、既存列の追加、削除、並べ替えは避けてください。

`価格` と `備考` はアプリで編集した現在値、`カタログ価格` と `シート備考` は更新元スプレッドシートの値です。アプリで追加した品目には、空欄からシート由来の値を作りません。旧15列・16列形式のシート品目を取り込む場合は、現在の `価格` と `備考` からシート由来値を推定して補完し、完了時に件数を表示します。旧形式には元の値が残っていないため、過去にアプリ側で変更した差までは復元できません。

完全版には元のGoogleスプレッドシートURL、品目URL、備考なども含まれます。第三者へ渡す前に、共有してよい情報か確認してください。

### イベント単位のExcelを取り込む

1. イベント一覧上部の「Excel取り込み」を選びます。イベントがまだない場合、ボタン名は「Excelファイルを取り込み」です。
2. このアプリから出力したイベント入出力XLSXを指定します。
3. 推奨の「別名で復元」か、現在の同名イベントを置き換える「同名で置換」を選びます。
4. ファイルの検証と保存がすべて完了すると、取り込んだイベントが開きます。

復元には `アイテムデータ` シートが必須です。「別名で復元」では既存イベントを変更せず、`イベント名（復元）`、`イベント名（復元2）` のような未使用名を初期値にします。「同名で置換」では、対象イベントを品目、メタデータ、配置、日別モード、マップ、回転、表示位置、ルート、ホール、ブロック検出設定の全セクションからいったん削除し、XLSXに含まれる内容だけで入れ替えます。そのため、簡易版や一部項目だけのXLSXを選ぶと、含まれないセクションは古い値を残さず削除されます。

復元は全セクションをまとめて保存し、途中で失敗した場合は現在のデータを変更しません。配置情報、マップデータ、ルート情報など任意データの一部を解析できない場合は警告を表示することがあります。回転、表示位置、ブロック検出設定の形式が不正な場合や、復元データ全体の整合性を確認できない場合は、復元画面を開く前に中止します。

完全版ではメタデータ内のイベント名が優先されるため、XLSXのファイル名を変えるだけでは別イベントになりません。旧版XLSXには回転、表示位置、ブロック検出設定が含まれないため、同名置換ではこれらも削除されます。必要な場合は先に現行版の完全版XLSXまたはJSONバックアップを保存してください。

### 3種類のファイルの見分け方

| 種類                 | 作成方法                  | 読み込む場所                                  | 主な内容                                             |
| -------------------- | ------------------------- | --------------------------------------------- | ---------------------------------------------------- |
| 会場マップXLSX       | Excelなどで新規作成       | イベントの三点メニュー → マップデータ取り込み | `1日目` などのシート、セル値、結合、罫線、塗りつぶし |
| イベント入出力XLSX   | イベントのExcel形式で出力 | イベント一覧 → Excel取り込み                  | 選択したイベントの品目、マップ・ルート情報           |
| 全データバックアップ | JSONバックアップ保存      | イベント一覧 → JSONバックアップ復元           | 全イベントと関連設定を含むバージョン付きJSON         |

## 保存先、オフライン利用、通信

イベント、品目、実行列、日別モード、マップ、ルート、ホール定義などは、通常ブラウザのIndexedDBへ約500ms遅延して自動保存されます。起動時は旧localStorageデータの移行とIndexedDBの初期読み込みを完了してから操作画面を表示します。

変更は約500ms遅延して、変更された保存領域だけを直列保存します。既定では画面右下に「未保存／保存中／保存済み」が表示されます。歯車の「保存状態を表示」をオフにすると通常の3状態は非表示になりますが、「保存失敗」は常に表示され、失敗した領域だけが再試行対象として残ります。未保存・保存中・保存失敗の状態でページを離れる場合は確認が表示されます。保存失敗時は「保存を再試行」を選び、必要ならその場でJSONバックアップを保存してください。

保存データは、利用中のブラウザ、ブラウザプロファイル、サイトのURLに紐づきます。IndexedDBもアプリ側では暗号化されません。クラウド同期は実装されていません。別端末、別ブラウザ、別の公開URLへは自動で移らず、サイトデータを削除すると失われます。

通常の個別自動保存では、IndexedDBへの書き込みが再試行後も失敗すると、マップ以外の保存領域をlocalStorageへ退避します。容量の大きいマップデータはlocalStorageへ退避されないため、保存失敗表示を放置しないでください。別端末へ移行・復元する標準手段として、全データJSONバックアップを定期保存してください。

永続化障害、旧localStorage移行、段階release、復旧時の運用手順は[永続化復旧runbook](docs/persistence-recovery-runbook.md)を参照してください。

PWA構成により、キャッシュ済みの画面、主要な閲覧・編集、ローカルファイル処理をオフラインで使える設計です。インストールまたはService Workerの有効化後、オンラインのまま再読み込みし、必要な画面を開いてから、実際の端末でオフライン動作を事前確認してください。次の操作には通信が必要です。

- Googleスプレッドシートからの新規取込と更新
- 初回アクセスと、まだキャッシュされていないアセットの取得
- アプリの更新確認と新バージョンの取得

ローカルXLSXは、ZIP/XMLのサイズ・件数・圧縮率を事前検査した後、専用Worker内で解析・生成します。CSVはブラウザ内で処理します。Googleスプレッドシート取込だけは、固定用途の同一オリジンAPIからGoogleのCSVエンドポイントへ接続します。画面スタイルとフォントはアプリ自身から配信し、Tailwind CDNや外部フォントへ接続しません。

更新を取得しても、開いているタブやインストール済みPWAを強制再読み込みしません。保存中の操作を終えて同一サイトの画面をすべて閉じると、Service Workerが自然に切り替わり、次回起動時に新しい版を使います。

Supabaseの認証、共有、Realtime同期、QR共有は現行機能ではありません。`syncQueue`は将来の共有機能ではなく、既存データとの互換性を保つために永続化・復旧対象として維持しています。

PWAとして使う場合は、HTTPSまたはlocalhostで開き、ブラウザの「アプリをインストール」または「ホーム画面に追加」を利用してください。

## トラブルシューティング

| 症状                                 | 確認すること                                                                            |
| ------------------------------------ | --------------------------------------------------------------------------------------- |
| Googleスプレッドシートを取得できない | シート名が正確に `品目表` か、共有URLが正しいか、未ログインで閲覧できるか、オンラインか |
| 一部の購入品だけ取り込まれない       | 対象行のM～Pに空欄がないか、1行目へデータを書いていないか                               |
| 貼り付けデータが拒否される           | M、N、O、P、Q、R、Wの順で、各行をちょうど7列にする                                      |
| 更新しても購入済み数量が変わらない   | 差分確認の「予定数量へ変更する」を明示的に選ぶ。実購入数は常に維持される                |
| マップ対象シートがないと表示される   | シート名を `1日目` 形式にし、イベント側の参加日と一致させる                             |
| ブロックが0件になる                  | 外周が連続した黒の中線・太線・二重線か、ラベルと番号が同じ領域か、番号が検出範囲内か    |
| 一部のブロックだけ見つからない       | ラベル文字数・文字種、領域の最大セル数、最低番号数、太線の途切れを確認する              |
| 1シートのブロック0件で取込が止まる   | 対象となる全 `○日目` シートで、少なくとも1つのブロックを認識できるようにする            |
| 品目がマップ番号へ出ない             | 参加日、ブロック表記、番号先頭の半角数字が一致しているか確認する                        |
| 右端や下端が切れる                   | 罫線や塗りだけでなく、意図したデータ範囲内に実値があるか確認する                        |
| マップの縦横比がExcelと違う          | 行高と列幅は使われず、正方形セルとして表示される                                        |
| 経路が通路を通らない                 | 通路の数字セルと白以外の塗りつぶしを取り除き、経路を連続させる                          |
| 経路が罫線を横切る                   | 罫線は経路の壁ではない。通行不可部分を白以外で塗る                                      |
| 別端末でデータが見えない             | ブラウザ保存は同期されない。元端末で全データJSONバックアップを保存して復元する          |

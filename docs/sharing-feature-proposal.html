参考WEBアプリ共有機能の考察 & 強化共有機能の提案

Context

現在のEvent Shopping Planner（巡回表）v1.9.0は、同人誌即売会の買い物リストをオフラインで管理するPWAだが、共有機能が一切ない。参考WEBアプリのリアルタイム共有機能を分析し、それを強化した共有機能を本アプリに追加する計画。最終的にはコード実装を視野に入れるが、まずは考察と提案を行う。

動画から確認した 参考WEBアプリの実際の使用フロー

  • 動画1（ホスト側）: ルーム「ホスト/ゲスト」二択 → ホスト選択 → ユーザーネーム設定 → 合言葉（5桁コード）自動生成・表示
  • 動画2（ホスト画面でのリアルタイム反映）: ゲストユーザーが特定スペースに「訪問中」となっている状態表示 + ゲストが購入ステータスを変更した際のリアルタイム同期反映

note記事「【C104】宝の地図を捨て、Notionを使ってコミケに参戦した話。」からの知見

akurusanによるNotionチーム買い物管理の実戦レポート（C104〜C106、4人チーム、200サークル規模）。

記事で紹介されたNotionデータベース構成

  • カラム: サークル名、棟別（東123/東456/東7/西12）、場所（01a等）、状態（未選択/購入前/購入完了/etc）、担当者、担当者メモ、頒布タイトル、頒布金額、希望数、希望メモ、画像、順番
  • ビュー: 個人タブ（担当者フィルター+順番昇順）、未完了タブ（グループ化+未完了フィルター）、絆リスト（更新時間順ソート）
  • Slack連携: Notionオートメーションで状態変更時にSlack通知（「購入完了(通知)」「限数購入(通知)」等）

記事から抽出した現場での臨機応変な再振り分けシナリオ（最重要）

  1. 「先に来たから買っちゃうよ！」: 西担当の人がまだ西で買い物中 → 自分が先に東7に到着 → Slackで連絡 → 担当者と順番をその場で書き換え投げつけ → リアルタイムで相手のリストから消え、自分のリストに追加
  2. 「このサークル、後回しにしよう」: 混雑で並べない → 順番を後ろに変更 → リスト上で自動的に後方に移動 → 後から戻ってきた時にリマインダー的に再表示
  3. 「限数がかかっていて買えない！」: 限数購入制限 → Slack通知（限数購入(通知)） → 他メンバーが自分の購入として追加分を購入
  4. 「これ買ってきて！」: 限数列で30分拘束中 → 他メンバーの未完了タブで空き状況を確認 → 「ヘルプいる？」→ 代理購入を依頼・担当者変更 → 約20分で完了（電話なら説明に時間がかかる）
  5. 二重購入防止: 担当変更がリアルタイムで反映 → 元の担当者のリストから即座に消える
  6. 金額変更の即時通知: 事前情報なしのサークルで購入 → 購入完了と同時に頒布金額を入力 → Slackで金額変更も通知

記事で指摘された紙リスト（宝の地図）の問題点

  • 打合せで漏れて買い忘れる
  • 打合せで数を間違える、合計で購入または少なく購入する
  • 並べる時間があることを選んでいるのにメモにより別の種類を選ぶ
  • 購入時のチェックミスで二重に買う、または買い忘れる
  • 机左右のabを間違える
  • WEBカタログのリストが同じ棟で複数ページになり最終ページのサークル全て買い忘れる

記事で指摘されたNotion運用の課題点（C105以降で改善中）

  • 予算管理: 「いくらお金を持っていけばいいか分かる親切な機能：予算」追加（C105）
  • タイムスタンプ: いつ・何分列に並んで買ったか記録できる機能追加（C106）
  • イマココ機能: どこで何分サークル列に並んでいるか分かる機能追加（C106）
  • MS Listsも検討: モバイルアプリのレイアウト問題、リアルタイム表示でない点で却下→Notion継続

1. 参考WEBアプリの技術分析

使用技術

要素 技術
リアルタイム同期 Firebase Realtime Database (ref().on('value'))
ローカル保存 IndexedDB v3 + localStorage フォールバック
認証 Firebase Anonymous Auth（デバイス単位のUID）
二重確保防止 ref().transaction() によるアトミック操作
UI フレームワークレス（素のDOM操作）
画像処理 Canvas API で800x800px/JPEG 0.75に圧縮

参考WEBアプリの共有フロー

  1. ルーム作成: 5桁の合言葉コード自動生成
  2. 参加: テンキーUIでコード入力 → Firebaseのrooms/{roomId}/membersに登録
  3. リアルタイム同期: アイテムの確保状態(gotBy)、完売状態(status='sold')をFirebaseリスナーで即時反映
  4. 二重確保防止: transaction()で「既に他メンバーが確保済み」の場合はロールバック+通知
  5. プレゼンス: onDisconnect()でオンライン/オフライン状態を自動管理
  6. 「向かっている」通知: ブースへの移動意思をリアルタイムでブロードキャスト

Firebase データ構造（ 参考WEBアプリ）

rooms/{roomId}/
  members/{memberId}/ → 名前、色、位置情報、オンライン状態
  spaces/{itemId}/
    subItems/{subId}/ → 確保状態、完売状態、gotBy
  batting/ → 「向かっている」リアルタイム通知

3. 強化共有機能の提案

[高優先度] 基盤機能（ 参考WEBアプリ同等 + 強化）

3.1 リアルタイムルーム共有

  • Firebase Realtime Database + Anonymous Authで実装
  • 5文字英数字のルームコード（36^5 = 6000万通り）
  • 最大5名参加、ルーム有効期限付き（イベント日+24h）
  • 強化点: 参考WEBアプリと同等の基本共有

3.2 QRコード共有

  • ルームコードをQRコード化し、画面に大きく表示
  • 会場で隣の友人にカメラで読み取ってもらうだけで参加可能
  • URLスキーム: https://{domain}/join/{roomCode}
  • 強化点: 参考WEBアプリにはない。会場の混雑時にコード手入力は困難

3.3 URLディープリンク + Web Share API

  • https://{domain}/join/{roomCode} でブラウザから直接参加
  • Web Share APIでLINE/Twitter/Discordへのネイティブ共有
  • コピーボタン+トースト通知のフォールバック
  • 強化点: 参考WEBアプリは合言葉のみ。URLならメッセージアプリから1タップで参加

3.4 二重購入防止（トランザクション）

  • Firebase runTransaction() で同一アイテムの重複確保を防止
  • 楽観的UI更新 → トランザクション失敗時にロールバック+通知
  • 「○○さんが既に確保しました」トースト表示
  • 強化点: 参考WEBアプリと同等（必須機能）

[高優先度] 現場での臨機応変な再振り分け機能群（note記事の実戦知見に基づく最重要差別化）

以下は記事で実際に発生した6つのシナリオをアプリ内で完結させるための機能群。 参考WEBアプリにもない、Notionでは「Slack+手動操作」で対応していた部分をワンタップUIで実現する。

3.5 リアルタイム担当者変更（ドラッグ&タップ再割り当て） --- 最重要

対応シナリオ: 「先に来たから買っちゃうよ！」「これ買ってきて！」

  • アイテムカード上のメンバーアバターをタップ → 担当者変更メニュー表示 → 1タップで再割り当て
  • 変更即座にFirebase同期 → 元の担当者のリストからリアルタイムで消え、新担当者のリストに追加
  • 「投げつけ」ボタン: 自分の未購入アイテムを一括で特定メンバーに渡すワンタップ操作
  • 「ヘルプ要請」ボタン: 列に並んで拘束中の時、空いているメンバーに通知を飛ばす
  • 受け取り側には「○○さんがヘルプを求めています（残り3件）」と表示
  • 承諾すると自動で担当者が切り替わる
  • Notion記事での課題: 担当者変更はできるが、Slackで連絡→Notionを開いて手動変更→相手も確認、と3ステップ必要だった。本アプリでは1タップで完結

3.6 購入順序のリアルタイム変更（後回し・前倒し）

対応シナリオ: 「このサークル、後回しにしよう」

  • アイテムカードをスワイプまたは長押し → 「後回し」ボタン → 巡回順の末尾に移動
  • 「前倒し」ボタン → 現在位置の次に挿入（急いで買いたい場合）
  • 順番変更は即座にFirebase同期 → フォーカスモードの案内順にも反映
  • 後回しアイテムのリマインダー: 一通り回った後、後回しにしたサークルが自動的にリストの先頭に再浮上
  • 既存のexecuteModeItems（巡回順）のリアルタイム同期で実現
  • Notion記事での運用: 順番フィールドを書き換えてリスト上の位置を変更していた。本アプリではスワイプ1つで完結し、ルート再計算も自動

3.7 限数購入・特殊状態の通知と連携

対応シナリオ: 「限数がかかっていて買えない！」「金額変更の即時通知」

  • 新しい購入ステータス追加: LimitedPurchase（限数購入）
  • 限数購入時の自動通知: 「○○さんが[サークル名]を限数購入しました（1部のみ）。追加購入が必要です」
  • 他メンバーが「追加購入を引き受ける」ボタンをタップ → 自動で同一サークルのアイテムが自分のリストに追加
  • 価格未定→購入時入力→即時通知: 事前に価格不明だったアイテムの金額を購入時に入力 → 全メンバーに金額通知
  • Notion記事での課題: Notionオートメーション+Slackで「限数購入(通知)」を実装。本アプリではアプリ内通知+ワンタップ対応で完結

3.8 メンバー空き状況の可視化と自動ヘルプマッチング

対応シナリオ: 「これ買ってきて！」（他メンバーの空き確認）

  • メンバーステータスバー: 各メンバーの現在の状態をヘッダーに常時表示
  • 「巡回中（残り12件）」「列に並び中（○○サークル/約15分）」「完了」「休憩中」
  • 未完了タブのチーム版: Notionの未完了タブに相当。メンバー別の残タスク数と進捗率をリアルタイム表示
  • 自動ヘルプ提案: あるメンバーが「列に並び中」で長時間拘束 + 別のメンバーが「残り2件」で余裕あり → 自動で「○○さんの代わりに買えるアイテムがあります」と提案
  • Notion記事での運用: 未完了タブで手動確認 → Slackで「ヘルプいる？」と連絡。本アプリでは空き状況が常時可視化され、自動マッチング提案まで行う

3.9 タスク初期割り振り（事前準備フェーズ）

対応シナリオ: 記事の「2日前の打合せ」フェーズ

  • 手動割り当て: アイテムごとにメンバーアバターをタップして担当者指定
  • 自動割り振り: 既存のA*経路探索(src/utils/pathfinding.ts)を活用し、各メンバーの総移動距離を最小化するように自動分配
  • ホール別一括割り当て: 「東123は○○担当、東456は△△担当」のようなエリア単位での一括割り当て（記事の「西12担当のメンバーと東456担当」に対応）
  • 優先度(highest)のアイテムは最も近い/速いメンバーに優先割り当て
  • 「自分のアイテム」フィルター: SummaryBarにトグル追加（Notionの「個人タブ」に相当）
  • 強化点: 参考WEBアプリにはタスク分担機能自体がない。Notionでは手動でカラムを埋める作業が必要だったが、本アプリでは経路最適化ベースの自動割り振りが可能

[中優先度] 状況把握・コミュニケーション機能

3.10 共有マップ上のメンバー表示

  • マップ上に各メンバーの現在位置（チェックインしたブース）をアバターで表示
  • 各メンバーのルートを色分けでオーバーレイ
  • 「向かっている」ブースに脈動するマーカー表示
  • タスク分担時は自分のルートをハイライト、他メンバーは薄く表示
  • 強化点: 参考WEBアプリにはマップ機能自体がない。記事のC106「イマココ機能」に相当するが、マップ上に可視化される点で遥かに直感的

3.11 チーム予算管理

対応シナリオ: 記事の「金額を忘れるな」「予算機能追加（C105）」

  • メンバーごとの支出合計（price * quantityで確保済みアイテム集計）
  • 購入時の金額入力: 事前に価格不明だったアイテムの金額をその場で入力 → 即時通知+予算に反映
  • チーム全体の予算上限設定 → 80%/100%でアラート
  • 持参金額の管理: 各メンバーが持っている現金残高を入力 → 残りの購入可能金額をリアルタイム表示
  • イベント後の精算計算（立て替え分の差額計算：「○○が△△の分を3,000円立て替え」→精算リスト自動生成）
  • Notion記事での課題: 「頒布金額」カラムに手入力。事前情報がないと空欄で、後から金額変更をSlack通知。本アプリでは予算ダッシュボードとして統合

3.12 アプリ内通知・クイックアクション（Slack代替）

対応シナリオ: 記事のSlack連携全般

  • 自動ステータス通知: 購入完了/限数購入/完売/担当者変更時にアプリ内トースト+通知パネル
  • クイックスタンプ: 「了解！」「完売でした」「長蛇の列」「合流しよう」「ヘルプいる？」「お疲れ！」
  • ワンタップアクション付き通知: 通知に「引き受ける」「後で」等のアクションボタンを付与
  • 例: 「○○さんが限数購入しました」→「追加分を引き受ける」ボタン
  • 例: 「○○さんがヘルプを求めています」→「対応する」ボタン
  • Firebase rooms/{code}/notifications/ に保存、折りたたみパネルで表示
  • Notion+Slackとの差: 2つのアプリを行き来する必要がなく、通知から直接アクション実行可能

3.13 購入タイムスタンプ・絆リスト（行動ログ）

対応シナリオ: 記事のC106「タイムスタンプ機能追加」「絆リスト」

  • 購入完了時に自動でタイムスタンプ記録
  • 絆リスト: 更新時間順でソートしたリスト → チーム全体の購入フローを時系列で把握
  • 「11:05 ○○が[サークルA]を購入」「11:08 △△が[サークルB]を完売報告」...
  • 移動時間分析: サークル間の移動にかかった時間を自動計算 → 次回イベントの計画改善に活用
  • 滞在時間記録: 列に並んだ開始〜終了時間 → 「このサークルは平均20分待ち」のデータ蓄積

[低優先度] 将来的な拡張

3.14 SNS共有（読み取り専用リスト公開）

  • 買い物リストを読み取り専用WebページとしてURL生成
  • Canvas→PNG画像エクスポートでTwitter/X投稿用
  • 「○○のコミケ戦利品」的な共有

3.15 ロールベース権限

  • オーナー（全権限）/ エディター（ステータス変更可）/ ビューアー（閲覧のみ）
  • 進捗を見守りたいだけの友人にビューアーロールを付与

3.16 オフライン同期強化

  • Firebase RTDBのenablePersistence()でオフライン書き込みキュー
  • 同期ステータスインジケーター（緑=同期済 / 黄=同期中 / 赤=オフライン）
  • 再接続時の自動リプレイとトランザクションによる競合解決

3.17 イベント振り返りレポート

  • イベント終了後に自動生成: 総購入数、総支出、メンバー別実績、完売率、移動効率
  • 「次回改善ポイント」の自動提案（例: 「○○ホールの到着が遅く完売3件」→「次回は○○を優先ルートに」）

4. 推奨技術スタック

要素 選定 理由
リアルタイムDB Firebase Realtime Database 参考WEBアプリで実績あり、オフライン永続化内蔵、無料枠十分
認証 Firebase Anonymous Auth ログイン不要でデバイス単位のUID発行
QRコード qrcode npm パッケージ 軽量（~30KB）、Canvas/SVG出力対応
ディープリンク Vercel rewrites + URLパース 既存のVercelデプロイに追加ルール
プッシュ通知 Firebase Cloud Messaging（将来） サービスワーカー既存、VAPID key追加のみ

コスト見積もり

  • Firebase Spark（無料）: 同時100接続、1GBストレージ、10GB/月ダウンロード
  • 1ルーム = 5接続 x ~40KBデータ → 同時20ルーム（100人）まで無料
  • それ以上はBlaze従量課金: イベント1日あたり約$5-10

データフロー

購入ステータス変更:

ユーザーが「確保」をタップ
  → (1) ローカルReact state即時更新（楽観的UI）
  → (2) IndexedDB保存（500msデバウンス、既存フロー）
  → (3) Firebase runTransaction()
      成功 → 完了 + activityLog追記 + 通知生成
      失敗（他メンバー確保済み） → ローカルstateロールバック+トースト通知
  → (4) Firebase → 他メンバーのリスナー → 他メンバーのstate更新 → UI反映

現場での再振り分け:

メンバーAが「ヘルプ要請」をタップ
  → (1) Firebase notifications/ に helpRequest 書き込み
  → (2) helpMatchingService が空きメンバーを判定
      → 残タスク少 + status='roaming' のメンバーBに通知
  → (3) メンバーBに「○○さんがヘルプを求めています」通知表示
      → 「対応する」ボタンをタップ
  → (4) Firebase items/{itemId}/assignedTo を A→B に変更
      → メンバーAのリストから消え、メンバーBのリストに追加
      → activityLog + 通知生成

後回し操作:

ユーザーがアイテムを「後回し」
  → (1) items/{itemId}/postponed = true, orderIndex = 9999
  → (2) フォーカスモードのリストから一旦消える
  → (3) 他の全アイテム完了後、後回しアイテムがリスト先頭に再浮上
  → (4) 「後回しにしたアイテムがあります」リマインダー通知

6. 検証方法

  1. ルーム作成/参加: 2つのブラウザタブで同一ルームに参加し、リアルタイム同期を確認
  2. 二重確保防止: 同時に同じアイテムを「確保」→ 片方のみ成功を確認
  3. 担当者リアルタイム再割り当て: タブAでアイテムの担当者を変更 → タブBのリストからリアルタイムで消えることを確認
  4. 後回し→再浮上: アイテムを後回し → 他アイテム全完了 → 後回しアイテムが先頭に再浮上
  5. ヘルプ要請フロー: タブAでヘルプ要請 → タブBに通知表示 → 「対応する」タップ → 担当者が切り替わる
  6. 限数購入通知: 限数購入ステータスに変更 → 他メンバーに通知 → 「追加購入を引き受ける」で自動アイテム追加
  7. QRコード: 生成されたQRをスマホカメラで読み取り→ 正しいURLに遷移
  8. オフライン: ネットワークをオフにして操作→再接続時に同期を確認
  9. 予算管理: 購入完了時の金額入力 → チーム予算ダッシュボードにリアルタイム反映
  10. タスク初期割り振り: 自動割り振りでメンバーごとの移動距離が均等化されているか確認

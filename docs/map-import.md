# マップのインポートとマップデータの取り扱い

このアプリでは、即売会の会場マップを `.xlsx` ファイルから取り込み、参加日ごとの `マップ` タブとして表示できます。取り込んだマップは、アイテムのスペース位置表示、実行リストへの追加、ホール別の巡回順、集中モードの地図表示に使われます。

## マップデータを取り込む

1. `イベント一覧` を開きます。
2. 対象の即売会リストのメニューを開きます。
3. `マップデータ取り込み` を選択します。
4. `.xlsx` ファイルを選択します。
5. `マップデータ取り込み` ダイアログで、必要に応じてブロック自動検出の詳細設定を調整します。
6. `プレビュー（ブロック検出）` を押して、検出結果を確認します。
7. 日別マップの初期角度を必要に応じて入力します。
8. `取り込む` を押します。

取り込みに成功すると、対象イベントのマップ情報がある参加日にマップアイコンが追加されます

## 取り込めるファイル

マップ取り込みで選択できるファイルは `.xlsx` です。アプリは Excel ファイル内のシートを読み取り、シート名が日付形式になっているものだけをマップとして解析します。

対象になるシート名:

```text
1日目
2日目
３日目
```

対象にならないシート名:

```text
1日目マップ
Day1
配置図
メモ
```

解析されたシートは、アプリ内ではシート名と同名の参加日にマップアイコンクリックで表示されます

## マップデータ（.xlsxファイル）の作り方

マップ取り込み用の Excel ファイルは、アプリの解析方法に合わせて作ると安定して読み込めます。基本方針は、`通路は空白または白いセル`、`通らせたくない場所は塗りつぶしセル`、`ブロックはブロック名セルと番号セルを太い罫線で囲む` です。

### 基本構成

1つの `.xlsx` ファイルに、参加日ごとのシートを作ります。シート名は `1日目`、`2日目` のようにします。

各シートには、会場マップをセルで表現します。

- 通路: 空白セル、または白塗りセル
- スペース番号: `1`、`2`、`26` のような整数セル
- ブロック名: `A`、`あ`、`ア`、`亜` のような文字(数値も可)セル
- 壁、柱、机、進入不可エリア: 白以外で塗りつぶしたセル
- ブロック境界: `medium`、`thick`、`double` の罫線

Excel 上の見た目をそのまま画像として保存するのではなく、アプリはセルの値、塗りつぶし、罫線、結合セルを読み取ってマップを再構成します。

### ルート描画で通れるエリアを作る

ルート描画では、セル単位で通れる場所と通れない場所を判定します。

通れるセル:

- 値が空のセル
- 背景色が未設定のセル
- 背景色が白のセル
- 数値以外の文字が入っていて、白以外で塗りつぶされていないセル

通れないセル:

- `1`、`26` のような数値セル
- `001`、`26` のような数字だけの文字列セル
- 白以外の背景色で塗りつぶされたセル

重要な点として、罫線だけではルートの通行可否は変わりません。太い罫線はブロック検出には使われますが、ルート探索では壁として扱われません。ルートを通したくない場所は、セルを白以外の色で塗りつぶしてください。

購入対象のスペース番号セルは通常は通れないセルとして扱われますが、ルートの始点・終点になっているセルだけは例外的に到達できます。そのため、番号セルを通路に置くのではなく、スペース位置として置いてください。

### 通路をきれいに描かせるコツ

ルートは上下左右の直交方向に進みます。斜め移動はしません。数値セルや塗りつぶしセルの近くは避けるように軽いペナルティがかかるため、通路に1セル以上の幅を持たせると、スペース番号に線が重なりにくくなります。

おすすめ:

- 通路は空白セルで連続させる
- 壁や机は白以外の塗りつぶしで表現する
- 通路の途中に数字だけのセルを置かない
- 通路として使いたいセルに背景色を付けない
- 視覚的な装飾色を通路に付けたい場合は、白以外の塗りつぶしを避ける

避けたい例:

- 会場全体を薄い色で塗りつぶす
- 通路セルに薄いグレーや水色を付ける
- 罫線だけで壁を作る
- 通路上に案内用の `1`、`2` など数字だけの文字を置く

### ブロックとして検出させるセル集団を作る

ブロックは、ブロック名セルを起点にして、太い罫線で囲まれた領域として検出されます。その領域内にある番号セルが、そのブロックのスペース番号になります。

基本形:

```text
┏━━━━━━━┓
┃   A   ┃  ← ブロック名セル
┣━━┳━━┳━━┫
┃ 1┃ 2┃ 3┃  ← 番号セル
┣━━╋━━╋━━┫
┃ 4┃ 5┃ 6┃
┗━━┻━━┻━━┛
```

作り方:

1. ブロック名を入れるセルを用意します。
2. ブロック名セルと、そのブロックに属する番号セルを同じ囲いの中に置きます。
3. ブロック全体を `medium`、`thick`、`double` の罫線で囲みます。
4. 番号セルには整数を入力します。
5. プレビューでブロック名と番号セル数を確認します。

ブロック境界には、細い罫線よりも `medium` または `thick` を使うのが安全です。点線や破線は見た目では太く見えても、ブロック境界として扱われない場合があります。

### ブロック名セルの作り方

ブロック名は、初期設定では最大4文字までの短い文字列として検出されます。カタカナ、ひらがな、英字、漢字、数字を含む名前が使えます。記号を含めたい場合は、取り込み時の詳細設定で記号を許可してください。

検出されやすい例:

```text
A
B
ア
島A
```

検出されにくい、または検出されない例:

```text
123
1234
配置エリアA
ブロックA詳細
3-01
```

数字だけのセルは、ブロック名ではなく番号セルとして扱われます。`3-01` のように数字と記号だけのブロック名を使う場合は、詳細設定で `記号` と `数字+記号のみのブロック名を許可` を有効にしてください。

ブロック名セルは、結合セルにしておくとプレビュー上で確認しやすくなります。初期設定では、ブロック名セルの最小結合セル数が `4` になっています。ただし、条件に合う短い文字列セルはブロック名候補になり得るため、会場メモや凡例の短い文字列が誤検出される場合があります。その場合は、詳細設定で許可文字種や最大文字数を調整してください。

### スペース番号セルの作り方

番号セルには、整数を入力します。

おすすめ:

- `1`、`2`、`26` のように数値で入力する
- `01` のような表示にしたい場合も、値としては数値 `1` にして表示形式で調整する
- 番号セルはなるべく結合しない
- 同じブロック内で同じ番号を重複させない

初期設定では `1` から `100` までの整数がスペース番号として検出されます。`101` 以上の番号を使うイベントでは、取り込み時に `数値セル（ブース番号）の範囲` の最大値を上げてからプレビューしてください。

アイテムとの照合では、アイテムのスペース番号の先頭の数字だけが使われます。たとえば、アイテム側が `26a`、`26b`、`26b1` の場合、マップ上では `26` の番号セルに対応します。

### 分割されたブロックを作る

同じブロック名が複数の場所に分かれている場合は、それぞれの領域に同じブロック名を置くと、アプリ内では同じブロックとしてまとめられます。

```text
┏━━ A ━━┓      ┏━━ A ━━┓
┃ 1  2 ┃      ┃ 3  4 ┃
┗━━━━━━┛      ┗━━━━━━┛
```

この場合、`A` ブロックの番号セルは `1, 2, 3, 4` としてまとめて扱われます。分割領域の中に別のブロック名が入っていると検出が乱れやすいため、別ブロックの名前は同じ囲いの中に入れないでください。

### 複雑な形のブロックを作る

L字型や階段状のブロックも、太い罫線で囲まれていれば検出できます。アプリは、四角形に収まらない領域をセルの集合として保持します。

複雑な形のブロックを作る場合のコツ:

- ブロックの外周を途切れない太い罫線で囲む
- 外周罫線の内側にブロック名セルを置く
- 同じブロック内の番号セルをすべて外周罫線の内側に置く
- ブロック内に別のブロック名を置かない
- 取り込み前にプレビューで強調表示して確認する

外周が開いていると、検出領域が外側へ漏れて、隣の通路や別ブロックまで同じ領域として扱われることがあります。

### 色付き罫線を使う場合

ブロック領域に黒以外の太い罫線が含まれている場合、アプリは同じ色の太い罫線を持つ番号セルも同じブロックの候補として追加することがあります。離れた番号セルを同じブロックとして補足したい場合には便利ですが、意図しない番号セルまで拾う可能性もあります。

安定させたい場合は、ブロックごとに罫線色を分けるか、通常の黒い太線で外周を囲んでください。

### 解析しやすいExcelを作るチェックリスト

- シート名は `1日目`、`2日目` の形式にする
- ブロック名は短くする
- ブロック名だけの凡例やメモをマップ外に置かない
- ブロック全体を `medium`、`thick`、`double` の罫線で囲む
- 番号セルは整数にする
- 番号セルの範囲が詳細設定に収まっているか確認する
- 通路は空白または白背景にする
- 進入不可エリアは白以外で塗りつぶす
- 通路や空き地を薄い色で塗らない
- プレビューでブロック名、番号セル数、簡易マップを確認してから取り込む

## イベントの参加日との対応

取り込んだマップは、対象イベント内に存在する参加日と対応する場合だけ保存されます。

たとえばイベント内のアイテムに `1日目` と `2日目` がある場合、Excel の `1日目` シートと `2日目` シートは取り込まれます。Excel に `3日目` シートがあっても、イベント側に `3日目` のアイテムがなければ取り込まれません。

取り込まれなかった日付がある場合は、取り込み完了時に `3日目はないので取り込みしませんでした` のようなメッセージが表示されます。

## プレビューで確認する内容

`プレビュー（ブロック検出）` を押すと、アプリが Excel から検出したブロック一覧と簡易マップが表示されます。

プレビューでは次を確認します。

- 必要な参加日のシートが検出されているか
- ブロック名が正しく検出されているか
- ブロックごとの番号セル数が大きくずれていないか
- 簡易マップ上でブロックの範囲が想定どおりか

複数シートがある場合は、プレビュー内のシートタブで日別マップを切り替えられます。ブロック名のボタンを押すと、そのブロックの範囲が簡易マップ上で強調表示されます。

## ブロック自動検出の詳細設定

自動検出がうまくいかない場合は、詳細設定を調整してから再度プレビューします。設定を変更すると、前回のプレビュー結果はクリアされます。

- `ブロック名の最大文字数`: ブロック名として扱う文字列の長さを制限します。
- `ブロック名の許可文字種`: カタカナ、ひらがな、英字、漢字、数字、記号をブロック名候補に含めるかを指定します。
- `数字+記号のみのブロック名を許可`: `3-01` のような名前をブロック名として扱います。
- `ブロック名セルの最小結合セル数`: ブロック名として扱う結合セルの最小サイズです。小さくすると候補が増えます。
- `数値セル（ブース番号）の範囲`: スペース番号として扱う数値の範囲です。
- `1ブロックあたりの最小ブース番号数`: 番号セルが少なすぎる領域をブロックとして扱わないための条件です。
- `1領域の最大セル数`: 自動検出で探索する領域の大きさの上限です。
- `多角形判定の閾値`: 四角形ではないブロック範囲を多角形として扱うかどうかの判定に使います。

詳細設定はイベント名ごとにブラウザの `localStorage` に保存され、次回同じイベントでマップを取り込むときに再利用されます。

## Excel から読み取られる情報

アプリは Excel シートから次の情報を読み取ります。

- セルの値
- 背景色
- 文字色
- 罫線
- 結合セル
- 縦書き設定
- シートの使用行・使用列

マップ描画では、これらをもとにセル単位のマップを再構成します。取り込み時には上下左右に余白が追加されるため、アプリ内の座標は Excel 上の行列番号と完全には一致しません。

## ブロックの検出方法

アプリは、ブロック名らしいセルを起点に、太めの罫線で囲まれた領域を探します。その領域内にある数値セルをスペース番号として扱い、ブロック定義を作成します。

同じブロック名が複数の領域に分かれている場合は、同じブロックとしてまとめられます。領域の形が四角形ではない場合は、セルの集合として保持されます。

番号セルは、詳細設定の `数値セル（ブース番号）の範囲` に入る整数だけが対象です。たとえば初期設定では `1` から `100` までの数値がスペース番号候補になります。

## アイテムとマップセルの対応

アイテムは、参加日、ブロック名、スペース番号を使ってマップ上のセルに対応付けられます。

対応条件:

- アイテムの参加日がマップの日付と一致する
- アイテムのブロック名がマップ上のブロック名と一致する
- アイテムのスペース番号の先頭の数字が、ブロック内の番号セルと一致する

たとえば `A-26a` や `A-26b1` のようなスペース番号は、先頭の `26` が番号セルとの照合に使われます。アルファベットや末尾の数字は、セル照合では無視されます。

ブロック名はまず完全一致で探されます。完全一致が見つからない場合は、大文字・小文字を区別しない一致が1件だけあるときに、そのブロックが使われます。

## 取り込み後に保存されるデータ

取り込んだマップは、元の `.xlsx` ファイルそのものとして保存されるのではなく、アプリ内で扱いやすい構造に変換されて保存されます。

主に保存される内容:

- 日別マップ名
- セル情報
- 結合セル情報
- 自動検出されたブロック定義
- マップの最大行・最大列
- 日別マップの初期回転角度

これらのデータはブラウザの IndexedDB に保存されます。ページを閉じても、同じブラウザ・同じアプリ環境であれば次回起動時に再読み込みされます。

## 既存マップがある場合

同じイベントにマップを再取り込みすると、取り込まれた日別マップだけが追加または上書きされます。Excel に含まれていない既存のマップデータは、そのまま残ります。

同じ日付のマップを取り込み直した場合、その日付のマップ本体と回転角度は新しい内容に更新されます。一方で、既存のホール定義やホール別の巡回順設定は自動では削除されません。レイアウトが大きく変わった Excel を取り込み直した場合は、取り込み後にホール定義や巡回順を確認してください。

## マップでの利用

取り込み後のマップ表示時では、次の操作ができます。

- マップ上でアイテムの対応セルを確認する
- セルを押して、そのスペースに紐づくアイテムを確認する
- セルから新規アイテムを追加する
- アイテムを実行リストへ追加する
- 実行リストの巡回ルートを表示する
- ホール定義を作成する
- ホール順序を設定する
- 表示倍率や地図の回転を調整する

ホール定義を設定すると、編集モード、実行モード、集中モードでホール単位の並びや巡回順に利用されます。

## 集中モードでの利用

集中モードでは、取り込んだマップを使って現在の訪問先、前後の訪問先、巡回ルートを表示できます。

フッターの地図アイコンで地図表示をオンにすると、PCでは地図とアイテムリストが左右に、スマートフォンでは上下に表示されます。マップ取り込み時に設定した初期角度は、地図回転のリセット先として使われます。

## エクスポート時の扱い

イベントを `完全版（.xlsx）` でエクスポートする場合、オプションで `マップデータ`、`ブロック定義`、`ホール定義`、`ルート情報` を含められます。

エクスポートされるマップデータは、元の会場マップ Excel ではなく、アプリが取り込み後に保持している内部データです。エクスポートした完全版ファイルを再インポートすると、マップデータ、ホール定義、ホールルート設定も復元できます。

`簡易版（.xlsx）` では、マップデータ関連の情報は含まれません。

## 取り込みに失敗した場合

取り込みやプレビューに失敗した場合は、次を確認してください。

- ファイル形式が `.xlsx` になっているか
- 対象シート名が `1日目`、`2日目` のような形式になっているか
- イベント内に同じ参加日のアイテムが存在するか
- ブロック名セルが検出条件に合っているか
- ブロック範囲が罫線で囲まれているか
- スペース番号が詳細設定の数値範囲内に入っているか

一部のシートだけ解析できなかった場合、そのシートはスキップされ、解析できたシートだけが取り込まれます。

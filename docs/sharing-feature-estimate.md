## MVP（最小実用製品）戦略

全機能を一度に実装するのではなく、段階的にリリースすることを推奨。

### MVP 1: 基本共有（Phase 0 + Phase 1） — 約5週間
**含む機能**: ルーム作成/参加、リアルタイムステータス同期、二重購入防止、QRコード、URLリンク共有
**この時点で可能なこと**: Sakuriと同等の共有体験 + QR/URL共有による改善
**リリース判断**: イベント前に最低限のチーム共有が必要な場合はここでリリース

### MVP 2: 再振り分け対応（+ Phase 2 の 3.5, 3.6, 3.7） — 追加約4週間
**追加機能**: リアルタイム担当者変更、後回し/前倒し、限数購入通知
**この時点で可能なこと**: note記事の主要シナリオに対応した臨機応変な運用
**リリース判断**: 次のコミケまでに間に合わせたい場合のターゲット

### MVP 3: フルチーム機能（+ Phase 2 残り + Phase 3） — 追加約8週間
**追加機能**: ヘルプマッチング、タスク初期割り振り、マップ表示、予算管理、通知、行動ログ
**この時点で可能なこと**: Notion+Slack運用を完全に代替するワンストップ体験

## バッファ・リスク係数

| リスク要因 | 影響 | 追加バッファ |
|------------|------|-------------|
| App.tsx 6,089行のモノリシック構造への統合 | 変更の副作用が予測しづらい | +10% |
| FocusMode.tsx 2,566行への後回しロジック統合 | 既存の巡回ロジックとの整合性 | +5% |
| Firebase初導入（既存依存3個→5個） | 学習コスト（Firebase未経験の場合） | +15% |
| 実機テスト（会場の低速回線シミュレーション） | オフライン→オンライン遷移の不具合 | +5% |
| 既存テスト164ファイルのリグレッション | 新機能追加による既存テスト破損 | +5% |

**リスク込み合計**: 105.5日 x 1.2〜1.4 = **約127〜148日（約6〜7ヶ月）**
